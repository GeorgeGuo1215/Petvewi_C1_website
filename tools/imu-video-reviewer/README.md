# 同帧：视频、IMU 与标签审阅工具

> 第一次下载？请先看 [让 AI 辅助安装与启动](../../LOCAL_SETUP_WITH_AI.md)，复制提示词让 AI 检查环境、安装缺失依赖并验证功能。

一个本地 Web 工具，用于同步检查视频、IMU 数据与动作标签，并导出修订后的标签 CSV。审阅在浏览器完成，自动视频修复由本机 Node.js 服务调用 FFmpeg 完成。

## 功能

- 导入本地视频
- 同时导入多份 IMU CSV，并按时间自动合并
- 导入 UTF-8 或 GB18030 编码的标签 CSV
- 用时间锚点对齐视频和 IMU 北京时间
- macOS 下自动识别视频左上角日期时间，采样首段、中段、尾段三帧校验后对齐
- 同步显示三轴加速度与角速度曲线
- 浏览、筛选和修改动作标签片段
- 允许标签片段没有对应 IMU 数据
- 导出 UTF-8 编码的修订版 CSV
- 播放失败时自动修复视频，支持进度查看、取消和下载修复版
- 数据不上传云端；修复时视频副本会传给本机服务并保存在本地

## 本地运行

需要 Node.js 18 或更新版本。进入项目目录后运行：

```bash
npm start
```

然后打开：

```text
http://127.0.0.1:8080
```

自动修复需要 FFmpeg。服务会查找 `FFMPEG_PATH`、系统 PATH、常见 macOS 安装目录，以及项目中的 `.local-tools/imageio_ffmpeg/binaries`。有 Python 时可在本目录安装项目专用工具：

```bash
python3 -m pip install --target .local-tools imageio-ffmpeg
npm start
```

Windows 可使用 `py -m pip install --target .local-tools imageio-ffmpeg`，或在 PowerShell 中设置 `$env:FFMPEG_PATH = 'C:\\tools\\ffmpeg.exe'` 再运行 `npm start`。前端和 Node 服务本身没有第三方 npm 依赖。

仅需审阅、无需自动修复时，也可以使用 Python 静态服务：

```bash
python3 -m http.server 8080
```

## 使用顺序

1. 载入视频文件。
2. 选择一份或多份 IMU CSV。
3. 载入标签 CSV。
4. 视频可播放且 IMU 已载入后自动识别左上角时间；也可点击“识别画面时间”重试，或点击“手动对齐”设置锚点。
5. 播放视频或拖动时间轴，同步检查画面、IMU 波形和标签。
6. 修改标签后点击“保存本段”，最后点击“导出标签 CSV”。

## 自动修复视频

载入视频后，浏览器报告无法播放时会自动开始修复，也可以点击视频右上角的“修复视频”。例如 `joa00011.mp4` 实际是 MPEG-PS 容器，可以自动重新封装成标准 MP4。

1. 优先无损重新封装，不重新编码视频。
2. 重新封装失败、或浏览器仍报告无法解码时，自动转为 H.264 / yuv420p（有损）。
3. 完成后自动载入修复视频，并提供“下载修复版 MP4”。

沿用所提供脚本的默认策略，修复版只保留视频，不含音频。输入副本、输出和日志保存在 `.local-data/repairs/<任务ID>/`，不会覆盖原始文件；此目录和修复工具目录均被 Git 忽略。单次最多 8 GB，同一时间处理一个任务。取消后保留已生成的中间文件；这些本地缓存不会自动清理，可在停止服务后按需自行清理。

修复只解决容器、编码及部分时间戳问题，不能恢复丢失的图像。转换可能改变视频时间起点，务必复核动作边界及 IMU 锚点，标签不会自动平移。已完成的修复版在重启服务后仍可读取；中断的任务需重新启动。

## 根据视频水印自动对齐

- 自动识别使用 macOS 自带 Vision 文字识别，需要 Xcode Command Line Tools（`xcode-select --install`）。首次识别会编译项目内的 Swift 小程序，保存在被 Git 忽略的 `.local-tools/` 中。其他系统保留手动锚点对齐。
- 视频左上角须有完整的 `YYYY-MM-DD HH:mm:ss` 水印。识别截取左上方区域，放大后只送到本机服务，不上传云端。
- 三帧分别取自视频首段、中段和尾段；要求时间递增、三帧估计的偏移相差不超过 1.5 秒，否则不自动应用，保留原对齐。可展开“查看识别依据”核对日期与时间。
- 按北京时间 UTC+8 解释水印，支持跨午夜；只有时分秒、日期缺失或不清晰时需要手动对齐。秒级水印带来约 ±1 秒误差，并非逐帧级校准。
- 视频是唯一播放时钟：拖动后 IMU 立即跳转；视频 0.5×、1×、2× 时，IMU 同步按相同速度前进，不改变原始采样值。
- 导入 IMU 不再自动假定其第一条对应视频第 0 秒。视频与 IMU 没有实际时间交集时会提示不重叠；跨文件数据空档显示为空。
- 自动识别使用独立解码器采样，不改变主播放器位置、播放速度或标签内容。

## GitHub Pages 与数据安全

在官网仓库中，源码位于 `tools/imu-video-reviewer/`，发布入口为 `/Petvewi_C1_website/imu-review/`。官网页脚提供入口。根目录的 Pages Action 将官网与工具一起部署，不会用工具替换官网首页。

只有 `index.html`、`styles.css`、`app.js`、`clock-sync.js`、`review-data.js` 被复制到公开站点。GitHub Pages 支持本地文件审阅、手动对齐、倍速同步及 CSV 下载；自动修复和水印识别按钮会禁用，需要在电脑上运行本目录的 `npm start`。

导出的 `*_reviewed.csv` 是新文件，不会覆盖原始 CSV，也不会提交回 GitHub。请确认下载成功后再关闭页面。CSV 保留原列、额外字段、原始行顺序；校验空时间、重复 ID 和非法区间。区间无需每秒一行，IMU 可完全不导入。修改的是选中区间及其边界，不会自动拆分相邻区间；重叠区间按 CSV 中第一条匹配显示，修改造成重叠时会要求确认。

编辑时暂停视频，未保存草稿不会被播放头切换覆盖；导出时会先保存有效草稿。无时区的 IMU 时间戳按北京时间解释，空传感器值不当作 0。方向键是固定 0.04 秒步进，不承诺任意帧率视频的精确逐帧。

视频、CSV、TSV、`data/`、`samples/`、本机缓存与工具目录已被 Git 忽略。仍应在提交前检查文件清单；不要强制添加私人数据。

## 测试

```bash
npm test
# 启动本机服务后，可选执行 FFmpeg 集成测试：
node scripts/check-repair-edges.mjs /path/to/ffmpeg
```

集成测试会在 `.local-data/` 生成测试视频与修复副本。可用 `TEST_URL` 指向独立测试端口。OCR 为近似对齐：三帧验证不能排除中间局部断点，应人工复核重要片段。
